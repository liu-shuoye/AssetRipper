# 2026-09-05

## 修复：Il2CppDumpManager 解析 System.Private.CoreLib 崩溃

- 现象：`FieldSerializer.TryCreateSerializableType` 抛 `System.IO.FileNotFoundException`（声明程序集 System.Private.CoreLib, 10.0.0.0 找不到），位于 AssetRipper.SerializationLogic/FieldSerializer.cs:39。
- 根因：外部 Il2CppDumper dump（.NET 6+ DummyDll）以 `System.Private.CoreLib` 而非 `mscorlib` 作为核心库作用域，但 `Il2CppDumpManager.Initialize` 仅用 Net100 参考程序集伪装了 `mscorlib`，运行时上下文缺 `System.Private.CoreLib` → AsmResolver 6.0.0 的 `Resolve` 在声明程序集缺失时抛 ResolutionException（而非返回 null），打破 `Try*` 方法的优雅降级约定。
- 修复：
  - `Il2CppDumpManager`：用参数化 `CreateCorLib(name, moduleName, version)` 同时注册 `System.Private.CoreLib`(v10.0.0.0，作主核心库) 与 `mscorlib`(v4.0.0.0，兼容旧版)；`Add` 在 RuntimeContext 建立前调用（仅登记 m_assemblies），再各 `runtimeContext.AddAssembly` 一次避免重复注册。
  - `FieldSerializer.cs`：line 39 与 line 276 的 `Resolve`/`CheckedResolve` 改为 `TryResolve`，将解析失败转为 `failureReason` 返回而非抛出。
- 注意：本环境仅装 .NET 8/9 SDK，无法编译 net10 工程；需在桌面会话 `dotnet build` 验证。Cpp2IL（IL2CppManager）路径的运行时上下文由 AssetRipper.Cpp2IL.Core 包内部构建，若 .NET 10 游戏在该路径也遇到同样错误，需在该 fork 内排查核心库命名。
