## 排查：Il2CppDumpManager 导出脚本出现 `\u002E` 转义

现象：`Slate.IDirectable.RootDisabled()` 被导出为 `Slate\u002EIDirectable\u002ERootDisabled()`。

结论：**不是 AssetRipper 在转码，根因在 Il2CppDumper 产出的 DummyDll 有损**。
- DummyDll 把显式接口实现写成普通私有方法，IL 名字保留点号（`Slate.IDirectable.RootDisabled`），
  但 **MethodImpl 表（0x19）行数为 0**，即没有 ECMA-335 的显式方法实现记录。
- 反编译器（`AssetRipper.ICSharpCode.Decompiler` 10.1.0.8388）拿不到显式接口实现信息，
  把点号当作 C# 非法标识符字符，按 DLL 内的格式串 `\u{0:x4}` 转义输出。

实测数据（纯 Python 解析 CLI 元数据表头）：
| 文件 | MethodImpl 行数 |
| --- | --- |
| Assembly-CSharp-firstpass.dll（DummyDll） | 表不存在（0） |
| Assembly-CSharp.dll（DummyDll） | 0 |
| System.Private.CoreLib.dll（Roslyn 真产物） | 4165 |

影响面：`Assembly-CSharp-firstpass.dll` 约 119 个、`Assembly-CSharp.dll` 约 75 个
显式接口实现方法名（接口名形如 `I`+大写开头），例如
`LitJson.IJsonWrapper.GetBoolean`、`BestHTTP.IProtocol.HandleEvents`、`Slate.IDirectable.RootDisabled`。

拟定的修复方向（尚未实现，等用户确认）：在 `Il2CppDumpManager.Initialize` 的
`RemoveDumpAttributes()` 之后新增一个 pass：
1. 遍历方法，名字含 `.` 时按 `接口全名.方法名` 拆分；
2. 解析接口类型 + 匹配接口方法，用 AsmResolver 的
   `TypeDefinition.MethodImplementations.Add(new MethodImplementation(接口方法, 本方法))` 补 MethodImpl；
3. 解析不到（接口未加载/签名不唯一）时兜底：把点号替换为下划线，保证输出可编译。
注意：接口必须是该类型 InterfaceImpl 列表中的成员，否则不能补 MethodImpl。
