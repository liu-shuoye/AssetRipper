## ComputeShader 源码还原导出（ComputeShaderExportMode）

**需求**：ComputeShader 导出能否像 Shader 还原那样得到可读代码。实测结论：Nikki4 的 ComputeShader 每个 kernel 的 `code` 字段**内嵌的就是 HLSLcc 生成的 GLES GLSL 文本源码**（hex 编码在 YAML 里），与 Shader 侧「随包不含编译字节码」同一事实——无需反编译，hex 解码即源码。`E:\Project\Unity\Nikki4\Assets\ComputeShader\*.asset` 16 个文件全部 kernel 载荷均为文本（已实测解码 `VFXCopyBuffer.asset` 验证 `#version 310 es ... void main()` 完整源码）。

**实现（新增导出模式 `ComputeShaderExportMode{ Yaml, Source }`）**：
- 新增 `ComputeShaderExportMode.cs`（`AssetRipper.Export/Configuration`）；`ExportSettings.ComputeShaderExportMode` 默认 `Yaml`（保持原 .asset 行为），`Source` 模式在 `ProjectExporter.Overrides.cs` 注册 `ComputeShaderSourceExporter`。
- 新增 `Shaders/ComputeShaderSourceExporter.cs`（遍历 `IComputeShader.Variants[].Kernels[]`，`#pragma kernel` + `#pragma numthreads` + 载荷；`IsLikelyText` 前 512 字节 ≥90% 可打印判定文本直通，否则注释标记二进制载荷）+ `Shaders/ComputeShaderExportCollection.cs`（扩展名 `compute`；meta 用 `ComputeShaderImporter_*` 版本类，19 段版本切换，pathID=0）。
- UI：`ComputeShaderExportModeDropDownSetting`（GUI.Web）+ `SettingsPage.g.cs` 手工补 `SetProperty` case 与 `WriteDropDownForComputeShaderExportMode`（预生成静态文件）+ `SettingsPage.cs` 挂到脚本/导出格式行空位。
- 本地化：en_US.json 5 键插在 `commands` 之后（ordinal 顺序：export_title < format_source < format_source_description < format_yaml < format_yaml_description）；zh_Hans.json 插在 shader 键后（CRLF 保持）。
- CodeWiki.md 第 7 节加「ComputeShader 源码还原」小节。

**关键接口事实（反射核实 SourceGenerated 1.3.14.2）**：
- `IComputeShader`：`Variants: AccessListBase<IComputeShaderVariant>`（Nullable 标注）、`Name_R: Utf8String`；`IComputeShaderVariant`：`TargetRenderer/TargetLevel/Kernels`（Kernels 为 Nullable 标注）；`IComputeShaderKernel`：`Name_R_Utf8String`/`Name_R_FastPropertyName`（class）、`Code: byte[]`、`ThreadGroupSize: AssetList<uint>`（3 值 = 64,1,1 小端）、`PreprocessedSource`。
- `ComputeShaderImporter` 无静态 `Create` 门面（区别于 `ShaderImporter.Create`），需自写版本切换；各版本类字段完全一致，切换仅为 meta 形状对齐。
- `.compute` 文件 Unity 用 `ComputeShaderImporter` 接管，meta 节点为 `ComputeShaderImporter`。

## 指定导入资源类型过滤（ImportAssetType 白名单）

**需求**：设置页多选 Unity 资源类型（Texture2D/Shader/Mesh 等），未选中者**不在加载阶段解析**（拦截 `GameAssetFactory.ReadAsset()`），导出时也不导出。经澄清确认：白名单语义（只导入选中）、放**导入设置**（加载即生效）、UI 用多选复选框组。

**实现**：
- 新增 `Configuration/ImportAssetType.cs`：面向用户的 14 个大类（Mesh/Texture/Material/Shader/AnimationClip/AnimatorController/AudioClip/Font/TextAsset/Sprite/GameObject/MonoBehaviour/ScriptableObject/VideoClip）。
- 新增 `Configuration/ImportAssetTypeExtensions.cs`：核心映射与判定，导入/导出两侧共用。`ClassIdsByType` 覆盖 100 个唯一 ClassID；反向查表用 `TryAdd`（首次登记优先，保证判定稳定）。关键方法 `IsClassIdAllowed(int classId, IReadOnlyCollection<ImportAssetType>?)`：**null=不过滤，空集合=全拒绝**（刻意区分）；`TryGetImportType`、`GetClassIds`。
- `ImportSettings`：`HashSet<ImportAssetType> ImportAssetTypes`（默认空）+ `bool EnableImportAssetTypeFilter`（默认 false）+ `[JsonIgnore] EffectiveImportAssetTypes`（开关关时返回 null）。加 `[JsonIgnore]` 是因为 `SettingsPageGenerator` 反射全部 public 属性，否则会多出控件。
- `GameAssetFactory`：构造函数加第 6 参 `IReadOnlyCollection<ImportAssetType>? allowedAssetTypes`，`ReadAsset` 开头过滤并 `return null`（上游 `SerializedAssetCollection` 两个调用点均已正确处理 null）。
- `GameStructure`：构造时传 `configuration.ImportSettings.EffectiveImportAssetTypes`，经 `InitializeGameCollection` 透传。
- `ProjectExporter.CreateCollections`：签名加 `CoreConfiguration options`，对 `FetchAssets()` 结果做**兜底过滤**（覆盖处理阶段合成/引擎内置资产），拦截时 `queued.Add(asset)` 标记已处理但不建集合。
- `SettingsPageGenerator.GetProperties()`：加类型过滤跳过非 boolean/enum/string/UnityVersion 属性，否则新属性导致生成器断言崩溃。
- `SettingsPage.cs`：手写 `WriteCheckBoxGroupForImportAssetTypes`（三列 + 全选/全不选）+ `ApplyImportAssetTypes`（**整体覆盖**，不增量合并）+ `ImportAssetTypesFieldName` 常量；checkbox value 用枚举名。
- `site.js`：新增 `setCheckBoxGroup(groupName, checked)`。
- 本地化：en_US / zh_Hans 各加 19 键；**注意 zh_Hans 原文件非字母序且键不完整**，故 `git checkout` 恢复后仅末尾追加，避免无意义大 diff。

**核心设计**：「总开关 + 类型集合」分离，解决「复选框全不选」歧义——全不选=什么都不导入，开关关=全量导入。双保险：加载拦截（真正省内存/时间）+ 导出兜底。

**端到端验证（反射调用真实程序集，ALL_PASS=True）**：把 `0Bins/AssetRipper.GUI.Free/Debug` 的 79 个依赖 DLL 拷进独立 probe 目录，`LoadFrom` + 反射调 `IsClassIdAllowed`/`TryGetImportType`，9 项全过：null 全放行、白名单内 Mesh/Shader 放行、白名单外 Texture2D/AudioClip 拒绝、空集合全拒、未归类 ClassID(787878) 拒绝、反向映射 Texture/Mesh 正确。**关键坑**：`Cpp2ILBridge` 的 `[ModuleInitializer]` 会让任何加载 `AssetRipper.Import` 的进程要求 `Cpp2IL.Core 1.0.5`（NuGet 有 1.0.9，必须从 `0Bins/AssetRipper.GUI.Free/Debug` 取 1.0.5）；且 probe 项目须 `GenerateDependencyFile=false`，否则 deps.json 钉死版本约束导致加载失败。另：`csc.exe` 在黑名单无法直调，改用独立 `dotnet build` 小工程编译（记得 export APPDATA/LOCALAPPDATA/ProgramData）。

**构建**：Rider MCP `build_solution_start` → `buildIsSuccess:true, problems:[]`。
