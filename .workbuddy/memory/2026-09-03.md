# 2026-09-03 工作日志

## Nikki4 Shader 被识别为 NamedObject 问题诊断与修复

### 现象
nikki4 模式加载 `bq_skeletondata.asset_locale.chinesesimplified`（UnityFS bundle，内含 CAB 序列化文件），
其中 PathID=-905636281508599772 的 Shader "Spine/Skeleton"（ClassID=48）被 GUI 识别为 NamedObject：
- 运行时 C# 类型是 Shader_Nikki4（Nikki4GameAssetProvider 分派正确，无读取报错）
- 但 `ClassName` = "NamedObject"（应为 "Shader"）
- YAML 导出为 `--- !u!48 &... \nNamedObject:` 空壳（无 m_ParsedForm/Blob 字段、m_Name 空）
- 名字列显示 "NamedObject"（空名回退类名）

### 根因（两层）
1. **ClassName**：SourceGenerated 生成类（Shader_2019_3_0_b0）由 AssemblyDumper Pass110_ClassNameAndIdOverrides
   注入 `ClassName => 原始名("Shader")` override；手写类 Shader_Nikki4 继承 NamedObject_2018_3（ClassID_130 类，
   ClassName="NamedObject"）却未复写 ClassName → 继承出 "NamedObject"。
2. **字段遍历/写路径**：Shader_Nikki4 采用"内部持有 m_Shader(Shader_2019_3_0_b0) + 属性委托"的组合模式
   （区别于 Material_Nikki4 等"直接继承具体版本生成类"），且未 override WalkStandard/WalkEditor/WalkRelease
   → YAML/JSON walker 走基类 NamedObject_2018_3 的字段（只 m_Name 等 4 字段）。

### 关键事实（调查中确认）
- 生成类 Shader_2019_3_0_b0 / NamedObject_2018_3 继承链：Shader_2019_3_0_b0 → NamedObject_2018_3
  （ClassID_130）→ EditorExtension_2018_3（ClassID_18）→ Object（ClassID_0）→ UnityObjectBase。
- 标准生成 Shader 也继承 NamedObject_2018_3！所以"基类是 NamedObject"本身没错，缺的是 Pass110 注入的 override。
- **Shader_2019_3_0_b0 是 sealed，无法改继承**（曾尝试以它为基类重构，编译失败）→ 只能保留
  NamedObject_2018_3 基类做增量修复。
- ExportYamlDocument 根节点 FieldName = asset.ClassName，root.Add(ClassName, map) 生成 YAML 类型名行，
  因此委托 m_Shader 遍历 + ClassName override 后 YAML 输出即标准 Shader 结构。
- 数据布局：Nikki4 Shader 对象数据 = [m_Name(空串)][ParsedForm(43 props ...)][Platforms/Offsets/…/Blob]
  [m_Code* blob][Dependencies][NonModifiableTextures][ShaderIsBaked][m_PapeFallbackShader]，
  真名 "Spine/Skeleton" 在 ParsedForm.Name（偏移 9716）。
- 复现/验证渠道：AssetRipper.GUI.Free.exe --port N --headless 起本地 Web，HTTP POST /Settings/Update
  (ImportSettings.GameType=Nikki4) + /LoadFile(Path=...)，GET /Collections|/Assets/Json|/Assets/Yaml 观察。
  已确认修复前行为；修复后需重新构建验证。

### 修复（Source/AssetRipper.Import/AssetCreation/Nikki4/Shader_Nikki4.cs）
在现有类上增量：
1. `public override string ClassName => "Shader";`
2. ReadRelease 末尾（ParsedForm.Name 赋值后）把名字同步到 Name_R 与基类：
   `m_Shader.Name_R = m_Shader.ParsedForm.Name; base.Name = m_Shader.ParsedForm.Name;`
   （注意基类链名字属性是 `Name`/`Name_C130`，不是 `Name_R`——Name_R 是具体版本生成类才有的）
3. `WalkStandard/WalkEditor/WalkRelease` 委托 `m_Shader.xxx(walker)`（需 using AssetRipper.Assets.Traversal）。

### 扩展修复（用户确认"全部一并修复"，同日）
排查发现同类"委托型"Nikki4 类共 9 个（基类泛化类 sealed 无法继承 → 内部 new 具体版本类委托），全部按上述模板修复：
- 覆盖列表：Shader(ClassID48)、Mesh(43)、ParticleSystem(198)、ParticleSystemRenderer(199)、
  SpriteRenderer(212)、TrailRenderer(96)、SkinnedMeshRenderer(137)、VisualEffect(2083052967)、
  AnimatorController(91)。各自 ClassName override + Walk 委托到内部 m_xxx；
  Mesh/AnimatorController 额外在 ReadRelease 读名字后同步 `base.Name`（它们的基类链含 NamedObject_2018_3 的 Name）。
- 组件类（Renderer/Component/Behaviour 系）无 m_Name，无需名字同步。
- 正确模式无需改：AnimationClip_Nikki4(Material 同款直接继承版本类)、Material_Nikki4、LineRenderer_nikki4。

### 编译注意（后续构建者必读）

- 若遇 CS0108/CS0114 警告属原有现象（手写属性名与链上成员重名），非本次引入。

## GameAssetFactory 调试落盘导致 DirectoryNotFoundException（已修复）

### 现象
导出 閃耀暖暖_4.1.2328503 时整个流程中断：
`DirectoryNotFoundException: Could not find a part of the path 'D:\UserData\errorData\Hidden\InternalErrorShader.Shader_Nikki4.bytes'`
调用链：MainAssetProcessor → FontExtensions.TryGetFontMaterial → PPtr 解析 → SerializedAssetCollection.EnsureAssetsLoaded
→ GameAssetFactory.TryReadNormalObject (GameAssetFactory.cs:199)。

### 根因
TryReadNormalObject 里有一段调试代码，把解析失败的资产原始字节写盘：
`File.Create($"D:/UserData/errorData/{asset.GetBestName()}.{asset.GetType().Name}.bytes")`。
资产名 `Hidden/InternalErrorShader` 含路径分隔符，Windows 下被当成子目录，
而 `errorData\Hidden` 不存在 → 抛异常直接冒泡，中断整个导入（AssetRipper.Settings 里没报错容错）。

### 修复（Source/AssetRipper.Import/AssetCreation/GameAssetFactory.cs）
- 抽出 `const string FailedAssetDataDirectory = "D:/UserData/errorData"`。
- 新增 `SaveFailedAssetData(asset, assetData)`：清洗文件名 → `Directory.CreateDirectory` 自动建缺失目录 →
  `using FileStream` 写入；整体 try/catch，IO 异常只 `Logger.Warning`，绝不中断主流程。
- 新增 `MakeSafeRelativePath(name)`：按 `/` `\` 分段，逐段替换 `Path.GetInvalidFileNameChars()` 为 `_`，
  丢弃 `""`/`.`/`..` 段（防目录穿越），全空则退化成 "Unnamed"。保留原目录层次（Hidden/ 仍为子目录）。
- 删除原 try 里"重置 reader 后再 Read 一次并忽略异常"的调试残留重读逻辑（会二次污染半初始化对象状态）。

### 注意
- 该调试落盘对每个失败资产都写一次，大规模导出时会有 IO 开销；后续可考虑加环境变量开关。
- 本会话无法编译验证（无 project.assets.json，restore 必崩），需用户本机构建。
- 幂等性：同名失败资产仍会互相覆盖（与原行为一致），未引入 PathID 后缀。
