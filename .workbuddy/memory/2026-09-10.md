## Texture2D 占位导出功能（StripTexture2DData）
- 需求：批量加载全部资源 OOM，加"不导出 Texture2D 但生成占位图保持引用"的功能。
- 实现（11 处修改）：
  - `ImportSettings.StripTexture2DData`（bool，默认 false）——**放 ImportSettings 而非 ExportSettings**，因为依赖方向 Export→Import，GameAssetFactory（Import 项目）读不到 ExportSettings。
  - `GameAssetFactory` 构造加 `stripTexture2DData` 参数（默认 false，DependenceGrapher 旧调用点免改）；`TryReadNormalObject` 中 `asset.Read()` 后剥离。

  - **关键坑 2**：只清 `ImageData_C28` 不够，`GetImageData()` 会回退读 StreamData 的 .resS 流（内存照样涨+导出真图）；两者都要清。
  - **关键坑 3**：清空后 `CheckAssetIntegrity()` 反而返回 **true**（`CheckIntegrity` 对空 Path 视为"无外部依赖"），PrimaryContent `TryCreateCollection` 的 integrity 前置检查因此要显式用 `PlaceholderMode ||` 放行。
  - `TextureConverter.TryCreatePlaceholderBitmap`：`DirectBitmap<ColorRGBA<byte>,byte>(w,h,1)` + `Bits.Fill(byte.MaxValue)` 纯白；depth 恒 1。
  - 导出器三处占位分支：TextureAssetExporter / LightmapTextureAssetExporter / PrimaryContent TextureExporter（构造注入 PlaceholderMode）；PrimaryContentExporter.cs:118 注册处传参。
  - SettingsPage.cs Export 分组加复选框；本地化键 `strip_texture_2d_data`（en_US/zh_Hans）。
- **关键坑 4**：LocalizationGenerator 的 SnakeCaseToPascalCase 对数字后的字母不大写：`strip_texture_2d_data` → `StripTexture2dData`（不是 2D）。
- 构建验证：Import / Export.PrimaryContent / Export.UnityProjects 全部 0 错误；GUI.Web 及上游因两个 SourceGenerator 项目缺 project.assets.json（本会话 restore 必崩的环境问题）未能构建，需桌面会话 `dotnet build` 后 headless 验证。

## 闪耀暖暖（Nikki4）实测：RuriDecompile 为何没走反编译 —— 已定位并修复
- 输入样本：`E:\BaiduNetdiskDownload\解包数据\nikki4\com.shining.nikki4.tw\閃耀暖暖_4.1.2328503\assets\art\shader\nn4\spine\nn4spineskeleton.shader`（真身是 **UnityFS bundle**，2019.4.25f1，不是文本 shader）。导出产物带 `//DummyShaderTextExporter` 标记 = 回退成了占位 shader。
- **两个叠加的原因（都已用 headless 实测证实）**：
  1. **平台门槛**：该 Shader 只声明 `m_Platforms = [9]` = **`Gles3x`**，而 `PreferredPlatforms = { D3D11, Vulkan }` → `PickBestPlatform` 返回 `Unknown` → **根本没尝试反编译**，直接回退 Dummy（且当时没有日志，完全静默）。
  2. **数据本体不是字节码**：即使强制到 Gles3x，6 个 blob 的 `ProgramData` 全是**文本**，库报 `Unsupported shader format: Unknown`。dump 出来看是 **HLSLcc 生成的 GLES GLSL 源码**（`hlslcc_mtx4x4unity_MatrixVP`、`UNITY_UNIFORM`、`#if HLSLCC_ENABLE_UNIFORM_BUFFERS`、`u_xlat*`/`SV_Target0` 命名），纯 ASCII、含完整 `void main`。这与 `Shader_Nikki4.StandardizeSubProgramData` 的注释一致：Nikki4 的 `"Pape"+9 字节头` 之后就是 GLSL 源码，**随包不含编译字节码**。
- **结论**：对闪耀暖暖这类资产，`Ruri.ShaderDecompiler` 在原理上不适用（它做的是 字节码→HLSL），不存在「该用它而没用」的问题。
- **本次修复（`ShaderRuriDecompileExporter.cs`，+156/-20）**：
  - **源码直通**：`ClassifyBinary()` 按魔数（DXBC / BC C0 DE / SPIR-V / 全可打印 ASCII）识别载荷；判定为文本时**不进反编译库**，直接构造 `DecompileResult { Success=true, SourceCode=文本, SourceLanguage="glsl", SourceFileExtension=".glsl" }`。库的 `VariantChainWriter.WriteBody` 原生支持这点（`hlsl ? UnityHlslAdapter.Adapt(...) : source`，注释写的是 "a foreign body passes through untouched"）。
  - 反编译请求改为**只收集需要反编译的 pass**（`decompileTargets` 下标映射），无请求时不实例化 `ShaderDecompiler`（不加载原生库）。
  - **平台门槛放开**：D3D11 → Vulkan → **资产声明的首个平台**（最后退路）。没有这一步，Nikki4 永远到不了源码直通。
  - 新增 `RURI_SHADER_DIAGNOSTICS=1`：打印资产声明的平台、选中平台、ParsedForm 有无，以及在 ParsedForm/blob/pass/符号表 哪一步退出；`ReadProgram` 里还会打印每个 pass 的 `ProgramData` 长度与**载荷类型分类**。这个开关是定位此类"静默回退"的关键。
- **实测结果**（默认设置，无任何环境变量）：`NN4/Spine/NN4Skeleton done (6/6 passes, 6 个随包源码直通, 2 variant files)`；产物 = `nn4spineskeleton.shader` + `nn4spineskeleton/Sub0_Pass0_Vertex_b2.glsl`、`Sub0_Pass1_Vertex_b1.glsl`（真实 GLES 源码）。验证输出在 `D:\tmp\ruri-repro\out4\...`。
