## Texture2D 占位导出功能（StripTexture2DData）
- 需求：批量加载全部资源 OOM，加"不导出 Texture2D 但生成占位图保持引用"的功能。
- 实现（11 处修改）：
  - `ImportSettings.StripTexture2DData`（bool，默认 false）——**放 ImportSettings 而非 ExportSettings**，因为依赖方向 Export→Import，GameAssetFactory（Import 项目）读不到 ExportSettings。
  - `GameAssetFactory` 构造加 `stripTexture2DData` 参数（默认 false，DependenceGrapher 旧调用点免改）；`TryReadNormalObject` 中 `asset.Read()` 后剥离。
  - **关键坑 1**：生成的接口 `ITexture2D.StreamData_C28` 是只读属性不能置 null（CS0200），要用扩展方法 `StreamData_C28?.ClearValues()` 清 Path/Offset/Size（`StreamingInfoExtensions`，需 using `AssetRipper.SourceGenerated.Extensions`）。
  - **关键坑 2**：只清 `ImageData_C28` 不够，`GetImageData()` 会回退读 StreamData 的 .resS 流（内存照样涨+导出真图）；两者都要清。
  - **关键坑 3**：清空后 `CheckAssetIntegrity()` 反而返回 **true**（`CheckIntegrity` 对空 Path 视为"无外部依赖"），PrimaryContent `TryCreateCollection` 的 integrity 前置检查因此要显式用 `PlaceholderMode ||` 放行。
  - `TextureConverter.TryCreatePlaceholderBitmap`：`DirectBitmap<ColorRGBA<byte>,byte>(w,h,1)` + `Bits.Fill(byte.MaxValue)` 纯白；depth 恒 1。
  - 导出器三处占位分支：TextureAssetExporter / LightmapTextureAssetExporter / PrimaryContent TextureExporter（构造注入 PlaceholderMode）；PrimaryContentExporter.cs:118 注册处传参。
  - SettingsPage.cs Export 分组加复选框；本地化键 `strip_texture_2d_data`（en_US/zh_Hans）。
- **关键坑 4**：LocalizationGenerator 的 SnakeCaseToPascalCase 对数字后的字母不大写：`strip_texture_2d_data` → `StripTexture2dData`（不是 2D）。
- 构建验证：Import / Export.PrimaryContent / Export.UnityProjects 全部 0 错误；GUI.Web 及上游因两个 SourceGenerator 项目缺 project.assets.json（本会话 restore 必崩的环境问题）未能构建，需桌面会话 `dotnet build` 后 headless 验证。
- 文档：docs/CodeWiki.md 第 7 节追加"Texture2D 占位导出"小节。

## CS0103 修复：SettingsPage.g.cs 是预生成静态文件
- 用户桌面构建报 CS0103（WriteCheckBoxForStripTexture2DData 不存在）。
- **根因**：`AssetRipper.GUI.SourceGenerator` 不是 Roslyn 生成器，而是**独立控制台工具**（Program.Main → CleanJsonLocalizationFiles + SettingsPageGenerator.Run，运行时反射 typeof(ImportSettings).GetProperties，把结果直接写到 GUI.Web 源码目录 `Pages/Settings/SettingsPage.g.cs`）。该 g.cs 是提交到仓库的静态文件，构建时不会自动更新——**新增设置字段后必须运行该工具或手工补 g.cs**（与之前探索报告说的"源生成器自动生成"不符）。
- 修复：手工按生成器规则补 g.cs 两处（booleanProperties 字典条目 + WriteCheckBoxForStripTexture2DData 方法，均按属性声明顺序插入 LoadDependencyMap 之后）；en_US.json 新键移到 ordinal 排序正确位置（static_mesh_separation 与 submesh_count 之间，因为 Program.CleanJsonLocalizationFiles 只重写 en_US.json 为 OrderBy(key) 顺序）。
- 修复后 GUI.Web、GUI.Free 构建 0 错误（用户桌面会话构建已补全 restore 缓存，本会话 --no-restore 构建随之可用）。
- 全链编译通过：Import / Export.PrimaryContent / Export.UnityProjects / GUI.SourceGenerator(工具本身 NETSDK1060 未验证但无关紧要) / GUI.Web / GUI.Free。

## 扩展占位导出到 Mesh / AudioClip
- ImportSettings 新增 `StripMeshData`、`StripAudioClipData`（bool），GameAssetFactory 构造扩为 5 参（后 4 个带默认值）。
- **Mesh 剥离**：`VertexData.Data = []`（内嵌顶点数据，加载期内存大头）+ `IndexBuffer = []` + `StreamData?.ClearValues()`——`IMesh.StreamData` 是 **IStreamingInfo** 类型（Mesh_Nikki4:281 证实），与 Texture2D 同款清法。`VertexData.Data` 可写（YamlStreamedAssetExportCollection.cs:40 先例）。
- **Mesh 导出占位**：工程模式 YAML 天然容错（YamlStreamedAssetExportCollection 空流时写空数据）无需改；PrimaryContent GlbMeshExporter 占位分支用 `new SceneBuilder()` + GlbWriter.TryWrite 写空场景合法 GLB。
- **AudioClip 剥离**：`AudioData = []`（老版本内嵌，可写）+ `Resource.Source = Utf8String.Empty`/Offset=0/Size=0（`IAudioClip.Resource` 是 **IStreamedResource?**，无 ClearValues 扩展，照 YamlAudioExportCollection.cs:30-32 先例手工清）。
- **AudioClip 导出占位**：工程模式 AudioClipExporter（Default/PreferWav）TryCreateCollection 里占位（解码在 TryCreate 而非 Export！），写空文件扩展名 ogg/wav 按格式设置；PrimaryContent AudioExportCollection 加 TryCreatePlaceholder。ExportInner 都改为允许空数组写文件（null 仍失败）。Native 模式占位不生效、Yaml 模式天然占位。
- SettingsPage.g.cs 按规则手工补齐（该文件预生成）；en_US.json 三键 ordinal 排序：strip_audio_clip_data < strip_mesh_data < strip_texture_2d_data（都在 static_mesh_separation 与 submesh_count 之间）。
- GUI.Free 全链 0 错误。CodeWiki.md 第 7 节改为"资源占位导出"三类型说明。
