# 2026-09-21

## 新增功能：导入完成后自动导出（用户不必再手动点导出）

### 需求
用户希望"选一次导入文件夹，导入结束就直接导出"，省去再切到导出页点击的步骤。

### 设计取舍
- 开关与目标导出方式放 **`ImportSettings`**（不是 ExportSettings）：① 这是导入阶段的行为；
  ② 设置页只在未加载资源时可编辑，而导出页恰好相反——放 Import 侧用户才能在导入前配置好。
- 枚举 `AutoExportKind`（None / UnityProject / PrimaryContent）放 **`AssetRipper.Import/Configuration/`**：
  `ImportSettings` 不能反向引用 `GUI.Web`，第一次放在 GUI.Web 里直接编译失败（CS0246）。
- 导出位置推断 `ResolveAutoExportBasePath`：优先上次记住的导出目录，否则取导入目录的
  **父目录**（同级），绝不写进导入目录内部 —— 避免导出产物和源资源混在一起。
- **自动导出强制追加时间戳子文件夹**：自动流程无法弹窗让用户确认"清空已有目录"，
  若不追加就可能静默删掉用户既有文件。这是关键安全约束，别为了"跟手动一致"去掉。
- 复用导出页原有的子文件夹命名：`MaybeAppendTimestampedSubfolder` 提升为
  `GameFileLoader.AppendTimestampedSubfolder`，`Commands` 侧改为转调，两边规则不再各写一份。
- `LastExportSettings` 增加 `ImportPath`，只在导入路径**确实是目录**时记录
  （多选文件无法唯一确定工作目录，写了反而更差）。

### 实测（HTTP 驱动真实 Nikki4 小样本，18899 端口）
- 设置写入 `AutoExportKind=PrimaryContent` → 设置页回显 selected 正确。
- `POST /LoadFolder` 后**未做任何手动导出操作**，日志依次出现：
  `Auto export enabled timestamped subfolder...` → `Starting primary content export`
  → `Attempting to export assets to C:\Unity\Nikki4Out\AssetRipper_export_20260921_021122`
  → `Finished exporting primary content.`（150/150）
- 落盘确认：`C:\Unity\Nikki4Out\AssetRipper_export_<时间戳>\{Assets,Assemblies}` 真实存在。
- 单测 `AutoExportTests`（5 例，路径推断与子文件夹拼接）全通过。

### ⚠️ 沙箱环境（本次踩坑）
- **后台进程在两次工具调用之间会被回收**：`Start-Process`、`cmd &`、`( cmd & )` 都撑不过一次
  工具调用边界。要做端到端 HTTP 验证，必须**在同一个 Bash 调用里**启动服务 + 发请求 + 收结果 + kill。
- `Select-Object -First N` 接在进程输出管道上会在 N 行后**关掉管道并终止进程**，别用它截日志。
- 验证用临时目录（`_autotest`）与临时导出目录跑完必须删；`Remove-Item` 被 safe-delete 拦，
  用 `[System.IO.File]::Delete` / `[System.IO.Directory]::Delete`。删除时只删自己创建的时间戳目录，
  别动用户既有的 `ExportedProject` / `AuxiliaryFiles`。
